# 스키마 마이그레이션 (Flyway)

이 디렉터리의 스크립트는 **운영 DB(TiDB)** 에 적용된다.

## 규칙

**파일명** — `V{버전}__{설명}.sql`

```
V2__add_member_quote_answer.sql
V3__add_notice_pinned.sql
```

- **V1 은 사용하지 않는다.** 운영 DB 에는 이미 스키마와 데이터가 있어 baseline 으로 진입했고,
  `baseline-version: 1` 이 "Flyway 도입 이전의 기존 스키마"를 가리킨다.
  **신규 마이그레이션은 V2 부터 시작한다.**
- 버전은 건너뛰지 말고 순차로 올린다.
- 설명은 소문자 snake_case.

## 하면 안 되는 것

**이미 적용된 파일을 수정하지 않는다.** `validate-on-migrate: true` 라 체크섬이 달라지면
다음 배포에서 부팅이 실패한다. 잘못 넣었으면 되돌리는 마이그레이션을 새 버전으로 추가한다.

**되돌릴 수 없는 변경(DROP COLUMN, DROP TABLE)은 신중하게.** 데이터가 사라지면 복구할 수 없다.
컬럼을 더 이상 쓰지 않게 되었다면, 먼저 코드에서 참조를 지우고 한동안 두었다가 별도로 정리한다.

## 배포 순서

컬럼 추가처럼 **코드가 새 컬럼을 요구하는 경우**, 마이그레이션이 먼저 돌아야 한다.
Flyway 는 애플리케이션 기동 시점에 실행되므로 이 순서가 자동으로 보장된다.

반대로 **컬럼을 제거하는 경우**는 코드 배포가 먼저다. 참조가 남은 채 컬럼이 사라지면 쿼리가 깨진다.

## 소유권

**`bff:app` 만 마이그레이션을 소유한다.** `bff:admin` 은 운영에서 같은 DB 에 붙으므로
`spring.flyway.enabled: false` 로 두었다. 양쪽이 동시에 마이그레이션하면 충돌한다.

## 로컬·테스트

| 환경 | 스키마 | Flyway |
|---|---|---|
| 운영 | TiDB, `ddl-auto: none` | ON |
| 로컬 | MySQL, `ddl-auto: none` | ON |
| 테스트 | H2, `ddl-auto: create-drop` | **OFF** |

테스트는 엔티티에서 스키마를 만든다. 마이그레이션 스크립트는 MySQL/TiDB 방언이라
H2 에서 실행하면 깨지므로 비활성화했다.

**따라서 마이그레이션 스크립트는 테스트로 검증되지 않는다.** 운영 반영 전 스테이징이나
로컬 MySQL 에서 한 번 돌려보는 것을 권한다.

## 기존 수동 DDL 문서

Flyway 도입 이전의 DDL 은 `docs/migration/*.md` 에 기록되어 있다.
해당 변경들은 이미 운영에 적용되어 baseline 에 포함되므로 다시 실행하지 않는다.

앞으로 스키마 변경은 이 디렉터리의 스크립트가 정본이며,
배경 설명이 필요하면 `docs/migration/` 에 문서를 함께 남긴다.
